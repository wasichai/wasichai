# ADR-071: Manuals in AsciiDoc beside the Markdown reference

**Status**: accepted · 2026-10-20 · builds on [ADR-032](0032-rebrand-to-wasichai-and-split-repositories.md) and
[ADR-033](0033-samples-and-infrastructure-in-their-own-repositories.md)

## Context

The docs here are a developer reference in Markdown: the REST API, one page per module, the guides, the ADRs and the
history. Nothing in them is written for the people who use or run an app: how to work with records, how to administer
users and permissions, how to install, back up and restore. Those readers want a book they can print or read offline,
in Spanish and in English, with real screenshots, and a demo database they can rebuild.

Markdown on GitHub has no cross-reference numbering, no figure or table captions, no includes and no PDF. A second
Markdown tree for the manuals would duplicate the reference and diverge from it.

## Decision

The manuals live in `docs/manuals/`, in AsciiDoc: a user, an administrator and a system manual, each in `es/` and
`en/` with the same files and anchors. Asciidoctor builds one HTML site and Asciidoctor PDF one book per manual and
language, with a theme of their own (IBM Plex, the light theme's colours of wasichai-ui) and the fonts in the
repository, so the output needs nothing remote.

- The Markdown reference stays canonical for what it covers. The manuals summarize it and link to it; they never copy
  it. The manuals are canonical for procedures and operations.
- The screenshots are taken by Playwright from the real UI: full-sample's web (`web/`, built against wasichai-ui
  next to it) and server, on the demo database. They are committed, regenerated by `docs:screenshots`.
- The demo database is loaded through the REST API from a committed fixture, so its tables are built by the platform
  as in any app; its plain-SQL export, manifest and integrity checks are committed too. The scripts take a URL and
  `WASICHAI_DB_*` and refuse a database that is not named `*_demo`; nothing assumes how the database or the app is run
  (ADR-033).
- The diagrams are Mermaid sources rendered to PNG, since the PDF converter cannot draw Mermaid's SVG labels.
- CI builds and validates the manuals (unresolved references, missing images, language parity, line length,
  secret-looking strings) but does not retake the screenshots: that needs a running app.

## Consequences

- The tools are Ruby (Asciidoctor, pinned by `Gemfile.lock`) and Playwright with Mermaid (pinned by
  `docs/manuals/package.json`), used by the manuals only. The library build is untouched.
- A UI or API change that alters a screen means new screenshots, and the chapter that describes it, in both languages.
- About 11 MB of screenshots and a half-megabyte SQL dump are in the repository, replaced when they are regenerated.
