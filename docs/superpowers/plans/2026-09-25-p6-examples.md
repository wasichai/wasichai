# P6 — Example Apps Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Four runnable example apps (`simple-sample`, `documents-sample`, `gis-sample`, `full-sample`), each a Spring Boot `server/` built only from the chawpi starters + BOM and a Vite React `web/` built only from the `@chawpi/*` packages it needs, each with a server smoke test, a web smoke test and a README, plus a repo-wide verification, a consumer check and a Playwright smoke on `full-sample`.

**Architecture:** Wave 0 makes every shared edit once (a `chawpi.sample-app` convention plugin, the four server build files, the four web `package.json` files, one `yarn install`, demo databases, ignore files, `examples/README.md`). Wave 1 builds the four samples in parallel, each task writing only inside its own `examples/<sample>/` folder. Wave 2 verifies the whole repo, proves the samples are never published, builds one sample against locally published artifacts, then runs the Playwright smoke.

**Tech Stack:** Kotlin 2.4.20, Spring Boot 4.1.1 (WebFlux, R2DBC), JDK 25, Gradle (repo wrapper), JUnit 5 + `chawpi-test`; React 19.3, Vite 8.3.0, Vitest 5.0.1, Tailwind 4.3.3, yarn 1.22 workspaces, `@playwright/test` 1.63.0.

**Spec:** `docs/superpowers/specs/2026-09-25-chawpi-libraries-design.md` (sections "Repository layout", "App developer experience", "Commits, versioning and releases", "Tests", "Verification").

- **Read-only for P6:** `backend/chawpi-integration-tests/` (P3 is running there), `backend/chawpi-*` library modules, `backend/starters/`, `frontend/packages/`, `/Users/jorge/IdeaProjects/sapgis`. Only Task 0 edits `backend/build-logic/` and `gradle/libs.versions.toml`.
- **Never port 5432** (the user's own tunnel may hold 5432 and 8081). Databases are reached through the ssh tunnel only: `5443` plain PostgreSQL 18, `5442` PostGIS, user/password `chawpi`/`chawpi`. Start it with `bash /private/tmp/claude-502/-Users-jorge-IdeaProjects-chawpi/73f54845-6d0f-493f-961b-10662da123e9/scratchpad/tunnel.sh` (prints `tunnel up` or `tunnel started`).
- **Test databases:** integration tests use `chawpi_test` through `chawpi-test`'s external mode and its suite lock (a second JVM waits, it never wipes a running suite). Every Bash call that runs a server integration test starts with this exact line (same values as P3's `it-env.sh`, inlined so P6 does not depend on a P3 file):
  `export CHAWPI_TEST_DB_HOST=localhost CHAWPI_TEST_DB_PORT=5443 CHAWPI_TEST_DB_NAME=chawpi_test CHAWPI_TEST_DB_USERNAME=chawpi CHAWPI_TEST_DB_PASSWORD=chawpi CHAWPI_TEST_GIS_DB_PORT=5442`
- **Demo databases** (bootRun / live boots / Playwright; never `_test`, so never wiped): `chawpi_simple` on 5443; `chawpi_documents`, `chawpi_gis`, `chawpi_full` on 5442. Created by Task 0.
- **Ports:**

  | Sample | Gradle project | Server port | Web workspace | Web port | Demo DB |
  |---|---|---|---|---|---|
  | simple-sample | `:simple-sample-server` | 8091 | `simple-sample-web` | 5171 | `chawpi_simple` @5443 |

- **Server dependencies:** only `platform(project(":chawpi-bom"))` + `chawpi-spring-boot-starter[-<module>]` projects, plus `testImplementation(project(":chawpi-test"))`. Main class uses `@ChawpiApplication` and nothing else. Packages `chawpi.examples.<simple|documents|gis|full>`.
- **Server config:** `application.yml` reads DB coordinates from `CHAWPI_DB_HOST/PORT/NAME/USERNAME/PASSWORD`; `chawpi.seed.dev: ${CHAWPI_SEED_DEV:true}` (login `admin@chawpi.local` / `admin`); GeoServer `enabled: ${CHAWPI_GEOSERVER_ENABLED:false}`. Only simple-sample has a DB port default (5433, compose profile `core`); documents-, gis- and full-sample have **no port default** (their compose database is the `postgres` service, whose published port is not ours to assume), so a missing `CHAWPI_DB_PORT` fails at startup instead of reaching 5432.
- **Web dependencies:** only the `@chawpi/*` packages the sample uses, at range `"*"`, plus their peers pinned to the versions the packages use (`react`/`react-dom` 19.3.0, `react-router` 8.4.0, `@tanstack/react-query` 5.103.1, `i18next` 26.4.2, `react-i18next` 17.0.14), `maplibre-gl` **exactly** 6.10.0 when gis is used, `"private": true`. Scripts: `dev`, `preview`, `lint` (prettier only), `test` (vitest), `build` (`tsc -p tsconfig.build.json && vite build`), `typecheck`.
- **Web test rule:** vitest resolves `@chawpi/*` to the sibling package **sources** (aliases, same as `frontend/packages/*`), so `yarn test` needs no build; `build` resolves the packages' **dist** through their `exports`, the way a consumer does. CI order is `yarn lint && yarn test && yarn build`.
- **Versions:** Kotlin 2.4.20, Spring Boot 4.1.1, JDK toolchain 25, Node >= 26, yarn 1.22.22, vite 8.3.0, vitest 5.0.1, `@vitejs/plugin-react` 6.1.1, tailwindcss + `@tailwindcss/vite` 4.3.3, TypeScript 5.9.3, prettier 3.8.2, `@playwright/test` 1.63.0 (its chromium 1243 is already in `~/Library/Caches/ms-playwright`).
- **Never published:** sample servers never apply `chawpi.publishing` (the `chawpi.sample-app` plugin refuses it) and their names do not start with `chawpi-`, so `chawpi-bom`'s `startsWith("chawpi-")` filter skips them; sample webs are `private: true` and live outside `frontend/packages/*`, the only folder `publish.yml`'s npm loop walks.
- **Wave 1 isolation:** a Wave 1 task writes only under `examples/<its sample>/`. It never runs `yarn install`, root `yarn build/test/lint`, root `./gradlew build`, and never edits `package.json` of its web (Task 0 owns it). It runs only `yarn workspace <its web> <script>`, `yarn prettier --write <its files>` and `./gradlew :<its sample>-server:<task>`. Root `yarn lint`/`yarn test` stay red until every Wave 1 task has written its web's `src`; nobody runs them at the root before then — Task 5 Step 4 is the first to do so.
- **Formatting:** before lint, run `yarn prettier --write` on the task's web files and `./gradlew :<sample>-server:ktlintFormat`; the code below is correct but whitespace is the formatters' call.

## Review Focus

1. **documents-, gis- or full-sample started without `CHAWPI_DB_PORT`** must stop at startup naming `CHAWPI_DB_PORT`, never fall back to 5432. Pinned in Task 2 Step 5, Task 3 Step 8 and Task 4 Step 5 (each sample's live boot without the variable).
2. **Tailwind not seeing the `@chawpi/*` class names** gives an unstyled but "working" app. The samples' own code has no utility classes, so a built CSS containing `.flex{` proves the `@source` works. Pinned in every Wave 1 web build step and in Task 5's consumer build.
3. **A sample leaking into a release** (BOM constraint, a Maven publication, an npm publish). Pinned by the plugin guard test in Task 0 and the POM/tasks/`private` checks in Task 5.
4. **simple-sample on plain PostgreSQL asked for a GEOMETRY field** must answer a 4xx, not a 500. Pinned in Task 1's server smoke test.
5. **gis-sample with no GeoServer running** must boot, list layers and serve features. Pinned in Task 3's server smoke test (GeoServer disabled by default, no GeoServer in the tunnel) and its live boot + perene run.

    @Test
    fun `sample app builds one boot jar named app jar`() {
        write("build.gradle.kts", "plugins { id(\"chawpi.sample-app\") }\n")
        write("src/main/kotlin/probe/App.kt", "package probe\n\nfun main() {\n    println(\"ok\")\n}\n")

        // assemble, not just bootJar: it also runs sourcesJar and jar, the two other places a plain
        // library convention leaks into an app's build/libs
        val result = runner("assemble").build()

        assertEquals(TaskOutcome.SUCCESS, result.task(":assemble")?.outcome)
        assertEquals(listOf("app.jar"), File(dir, "build/libs").list()?.sorted())
    }

    @Test
    fun `sample app refuses to be published`() {
        write("build.gradle.kts", "plugins {\n    id(\"chawpi.sample-app\")\n    id(\"chawpi.publishing\")\n}\n")

        val result = runner("help").buildAndFail()

        assertTrue(result.output.contains("example apps are never published"))
    }

    @Test
    fun `sample app build succeeds with only integration-tagged tests`() {
        write("build.gradle.kts", "plugins { id(\"chawpi.sample-app\") }\n")
        write("src/main/kotlin/probe/App.kt", "package probe\n\nfun main() {\n    println(\"ok\")\n}\n")
        // like every sample's smoke test: integration-tagged only, so the plain `test` task discovers
        // zero tests once chawpi.kotlin-library's excludeTags("integration") filters them out
        write(
            "src/test/kotlin/probe/ProbeSmokeTest.kt",
            """
            package probe

            import org.junit.jupiter.api.Tag
            import org.junit.jupiter.api.Test

            class ProbeSmokeTest {
                @Test
                @Tag("integration")
                fun `integration tagged test`() {
                    // never run by the plain test task
                }
            }
            """.trimIndent() + "\n",
        )

        val result = runner("build").build()

        assertEquals(TaskOutcome.SUCCESS, result.task(":build")?.outcome)
        assertEquals(listOf("app.jar"), File(dir, "build/libs").list()?.sorted())
    }

- [ ] **Step 4: Write the plugin**

Create `backend/build-logic/src/main/kotlin/chawpi.sample-app.gradle.kts`:

```kotlin
import org.springframework.boot.gradle.tasks.bundling.BootJar

// an example app: a spring boot application assembled from the chawpi starters. never published:
// chawpi-bom's constraints only take projects named chawpi-*, and this plugin refuses maven-publish.
plugins {
    id("chawpi.kotlin-library")
    id("chawpi.integration-test")
    id("org.jetbrains.kotlin.plugin.spring")
    id("org.springframework.boot")
}

pluginManager.withPlugin("maven-publish") {
    throw GradleException("${project.path} is an example app: example apps are never published")
}

// one runnable jar with a fixed name: live boots and the playwright smoke start it without globbing
tasks.named<BootJar>("bootJar") {
    archiveFileName.set("app.jar")
}

// an app, not a library: no plain jar next to the boot jar
tasks.named<Jar>("jar") {
    enabled = false
}

// an app, not a library: no sources jar next to the boot jar either
tasks.named<Jar>("sourcesJar") {
    enabled = false
}

// an app's smoke tests are all integration-tagged: an empty unit run is expected
tasks.named<Test>("test") {
    failOnNoDiscoveredTests.set(false)
}
```

// the smoke test needs PostGIS: the postgis image under testcontainers, or the external PostGIS
// server (CHAWPI_TEST_GIS_DB_PORT; database name, user and password are shared with the plain one)
val externalDb = providers.environmentVariable("CHAWPI_TEST_DB_HOST").isPresent
val gisDbPort: String? = providers.environmentVariable("CHAWPI_TEST_GIS_DB_PORT").orNull

tasks.named<Test>("integrationTest") {
    systemProperty("chawpi.test.db.image", "postgis/postgis:18-3.6")
    if (gisDbPort != null) environment("CHAWPI_TEST_DB_PORT", gisDbPort)
    val missingGisPort = externalDb && gisDbPort == null
    doFirst {
        if (missingGisPort) throw GradleException("gis-sample-server needs PostGIS: with CHAWPI_TEST_DB_HOST set, also set CHAWPI_TEST_GIS_DB_PORT")
    }
}

            .uri("/api/objects/$objectName/records/$record/documents/oficio")

            .isCreated
            .expectBody()
            .jsonPath("$.status")
            .isEqualTo("VALID")

            .uri("/api/objects/$objectName/records/$record/history")
            .header(HttpHeaders.AUTHORIZATION, token)
            .exchange()
            .expectStatus()
            .isOk
            .expectBody()
            .jsonPath("$[0].operation")
            .isEqualTo("ISSUE")

    // documents and automation meet only through automation's optional DocumentIssuer port:
    // this sample has both, so a GENERATE_DOCUMENT action issues for real
    @Test
    fun `an automation issues a document when a record is created`() {
        post(
            "/api/objects/$objectName/automations",

                "label" to "Oficio al crear",

        // the background drain polls every second
        val deadline = System.nanoTime() + Duration.ofSeconds(30).toNanos()

            Thread.sleep(250)

            .expectStatus()
            .isCreated
            .expectBody()
            .returnResult()
            .responseBody

            .orEmpty()

                .isOk
                .expectBody()
                .returnResult()
                .responseBody
                ?.decodeToString()
                .orEmpty()

    private fun paragraph(vararg content: Map<String, Any?>): Map<String, Any?> = mapOf("type" to "paragraph", "content" to content.toList())

    private fun text(value: String): Map<String, Any?> = mapOf("type" to "text", "text" to value)

// sapgis's manual flows, headless: login, an object with a GEOMETRY field, its record with the map,

const unique = (prefix: string) => `${prefix}${Date.now().toString(36)}${Math.random().toString(36).slice(2, 6)}`

async function send(request: APIRequestContext, token: string, method: 'get' | 'post' | 'put', path: string, data?: unknown, status = 200) {
  const response = await request[method](`/api${path}`, { headers: { Authorization: `Bearer ${token}` }, data })
  expect(response.status(), `${method.toUpperCase()} ${path}`).toBe(status)
  return response.json()
}

  const login = await request.post('/api/auth/login', { data: ADMIN })
  expect(login.status()).toBe(200)
  const { token } = (await login.json()) as { token: string }

  const object = unique('e2e')
  const prefix = unique('E').toUpperCase().slice(0, 10)
  await send(
    request,
    token,
    'post',
    '/objects',
    {
      name: object,
      label: 'Predio E2E',
      pluralLabel: 'Predios E2E',
      fields: [
        { name: 'codigo', label: 'Codigo', type: 'TEXT' },
        { name: 'lote', label: 'Lote', type: 'GEOMETRY', geometryType: 'POLYGON', srid: 4326 }
      ]
    },
    201
  )
  await send(request, token, 'put', `/objects/${object}/workflow`, {
    name: unique('wf'),
    label: 'Aprobacion',
    enabled: true,
    definition: {
      states: [
        { name: 'draft', label: 'Borrador', type: 'INITIAL' },
        { name: 'approved', label: 'Aprobado', type: 'FINAL' }
      ],
      transitions: [{ name: 'approve', label: 'Aprobar', from: 'draft', to: 'approved', roles: [] }]
    }
  })
  await send(
    request,
    token,
    'post',

    201
  )
  const record = (await send(
    request,
    token,
    'post',
    `/objects/${object}/records`,
    { attributes: { codigo: 'P-1' }, geometries: { lote: { type: 'Polygon', coordinates: [RING] } } },
    201

  await page.getByLabel('Contraseña').fill(ADMIN.password)
