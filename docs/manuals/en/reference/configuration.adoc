[[sys-configuration]]
== Configuration

The application is configured with Spring Boot properties (`application.yml`, environment variables, arguments).
No module ships an `application.yml`: the defaults are in the `@ConfigurationProperties` classes and in
`WasichaiEnvironmentPostProcessor`, which supplies, with the lowest priority, the database connection from the
`WASICHAI_DB_*` variables. Spring accepts the environment variable form of any property:
`wasichai.gis.geoserver.enabled` → `WASICHAI_GIS_GEOSERVER_ENABLED`.

=== Environment variables

[cols="2,1,3",options="header"]
|===
|Variable |Default |Use
|`WASICHAI_DB_HOST` |`localhost` |PostgreSQL server.
|`WASICHAI_DB_PORT` |`5432` |Port.
|`WASICHAI_DB_NAME` |`wasichai` |Database.
|`WASICHAI_DB_USERNAME` |`wasichai` |User.
|`WASICHAI_DB_PASSWORD` |`wasichai` |Password. *Secret.*
|`WASICHAI_JWT_SECRET` |_(none)_ |HMAC key of the JWTs, at least 32 bytes. Without it the application does not
start. *Secret.*
|`ANTHROPIC_API_KEY` |_(empty)_ |Key of the assistant (agent module). Without it the assistant is disabled.
*Secret.*
|`PORT` |`8090` |HTTP port of `full-sample` (defined in its `application.yml`).
|===

Secrets are supplied by the runtime environment (secret manager, protected CI variables); they are never written in
`application.yml` or in the repository. The database defaults are for development.

=== Example production configuration

[source,yaml]
----
# application-prod.yml of your own application. Secrets arrive through environment variables.
server:
  port: 8080
wasichai:
  security:
    jwt:
      secret: ${WASICHAI_JWT_SECRET}
      ttl: 4h
      revocation: true
    login:
      enabled: true
    password:
      min-length: 12
      require-digit: true
      not-equal-email: true
  web:
    cors-allowed-origin-patterns: [ "https://licencias.example.org" ]
  gis:
    geoserver:
      url: https://geoserver.internal.example.org/geoserver
      username: ${GEOSERVER_USER}
      password: ${GEOSERVER_PASSWORD}
----
